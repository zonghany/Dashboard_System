## ADDED Requirements

### Requirement: 基于 JWT 的无状态用户认证
系统必须为所有用户访问提供基于 JWT 的无状态认证机制。

#### Scenario: 用户使用有效凭据注册
- **WHEN** 用户提交包含有效邮箱格式和符合强度要求的密码（至少 8 位，包含大写字母、小写字母和数字）的注册表单
- **THEN** 系统必须创建新用户账户，使用 BCrypt 加密存储密码，发送验证邮件，并返回 HTTP 201 和成功响应

#### Scenario: 用户使用无效邮箱格式注册
- **WHEN** 用户提交不符合标准邮箱格式的注册表单（如缺少 @ 或域名）
- **THEN** 系统必须返回 HTTP 400，错误消息为 "邮箱格式无效"

#### Scenario: 用户使用弱密码注册
- **WHEN** 用户提交的密码少于 8 位，或缺少大写字母，或缺少小写字母，或缺少数字
- **THEN** 系统必须返回 HTTP 400，明确指出未满足的密码强度条件

#### Scenario: 用户使用已注册的邮箱注册
- **WHEN** 用户提交一个系统中已存在的邮箱的注册表单
- **THEN** 系统必须返回 HTTP 409，错误消息为 "该邮箱已被注册"

#### Scenario: 用户使用有效凭据登录
- **WHEN** 用户提交包含已注册邮箱和正确密码的登录表单
- **THEN** 系统必须验证凭据，生成有效期为 7 天的 JWT 令牌，并返回令牌和用户profile信息

#### Scenario: 用户使用错误密码登录
- **WHEN** 用户提交已注册邮箱但密码错误的登录表单
- **THEN** 系统必须返回 HTTP 401，错误消息为 "邮箱或密码错误"

#### Scenario: 用户使用未注册的邮箱登录
- **WHEN** 用户提交系统中不存在的邮箱的登录表单
- **THEN** 系统必须返回 HTTP 401，错误消息为 "邮箱或密码错误"（不透露邮箱是否存在）

#### Scenario: JWT 令牌过期
- **WHEN** 用户使用超过 7 天有效期的 JWT 令牌发起 API 请求
- **THEN** 系统必须返回 HTTP 401，前端必须清除本地存储的令牌并跳转到登录页面

#### Scenario: 用户无令牌访问受保护路由
- **WHEN** 用户在未提供 JWT 令牌的情况下尝试访问任何受保护的页面或 API 端点
- **THEN** 系统必须返回 HTTP 401，前端必须跳转到登录页面

#### Scenario: 用户使用格式错误的令牌访问受保护路由
- **WHEN** 用户使用格式被篡改或损坏的 JWT 令牌尝试访问受保护的 API 端点
- **THEN** 系统必须返回 HTTP 401，错误消息为 "无效的认证令牌"

#### Scenario: 用户登出
- **WHEN** 用户点击"退出登录"按钮
- **THEN** 前端必须清除本地存储的 JWT 令牌，关闭所有活跃的 WebSocket 连接，并跳转到登录页面

#### Scenario: 令牌临近过期时自动刷新
- **WHEN** 用户持有有效 JWT 令牌且距离过期不足 24 小时时继续使用系统
- **THEN** 系统必须在下次成功 API 调用的响应头中自动颁发新的 7 天 JWT 令牌

### Requirement: 密码安全
系统必须强制执行安全的密码存储和校验。

#### Scenario: 密码使用 BCrypt 存储
- **WHEN** 创建新用户账户或更新密码时
- **THEN** 系统必须在持久化到数据库之前使用工作因子至少为 10 的 BCrypt 算法对密码进行哈希

#### Scenario: API 响应中永不返回密码
- **WHEN** 任何 API 响应包含用户数据时
- **THEN** 系统必须在响应体中永远不包含密码哈希
