## ADDED Requirements

### Requirement: 项目创建时自动分配管理员角色
系统必须允许已认证用户创建项目，并自动将其设置为项目管理员。

#### Scenario: 已认证用户创建项目
- **WHEN** 已认证用户提交包含有效项目名称和描述的项目创建表单
- **THEN** 系统必须创建新的项目记录，将创建用户设置为项目管理员，并返回 HTTP 201 的项目详情

#### Scenario: 未认证用户尝试创建项目
- **WHEN** 未认证用户尝试创建项目
- **THEN** 系统必须返回 HTTP 401

#### Scenario: 项目名称为空时创建项目
- **WHEN** 用户提交空或仅包含空白字符的项目名称的项目创建表单
- **THEN** 系统必须返回 HTTP 400，错误消息为 "项目名称不能为空"

#### Scenario: 项目名称超出最大长度时创建项目
- **WHEN** 用户提交项目名称超过 100 个字符的项目创建表单
- **THEN** 系统必须返回 HTTP 400，错误消息为 "项目名称不能超过100个字符"

### Requirement: 通过邮件邀请成员
系统必须允许项目管理员通过邮件邀请链接邀请成员加入项目。

#### Scenario: 管理员通过邮件邀请新成员
- **WHEN** 项目管理员提交包含系统中已注册邮箱地址的有效邀请
- **THEN** 系统必须发送包含唯一邀请链接的邀请邮件，并创建待处理的成员记录

#### Scenario: 受邀用户接受邀请
- **WHEN** 受邀用户点击邮件中的邀请链接
- **THEN** 系统必须将用户添加到项目成员列表（角色为"普通成员"），并将用户重定向到项目页面

#### Scenario: 邀请链接过期
- **WHEN** 受邀用户在链接超过 48 小时后点击邀请链接
- **THEN** 系统必须显示错误消息 "邀请链接已过期，请联系项目管理员重新发送邀请"

#### Scenario: 管理员邀请已是成员的邮箱
- **WHEN** 项目管理员尝试邀请已属于同一项目成员的邮箱地址
- **THEN** 系统必须返回 HTTP 409，错误消息为 "该用户已是项目成员"

#### Scenario: 非管理员尝试邀请成员
- **WHEN** 角色为"普通成员"的用户尝试邀请新成员
- **THEN** 系统必须返回 HTTP 403，错误消息为 "仅项目管理员可以邀请成员"

#### Scenario: 邀请链接已被使用
- **WHEN** 用户点击已被成功使用过的邀请链接
- **THEN** 系统必须显示消息 "您已加入该项目" 并重定向到项目页面

### Requirement: 基于角色的项目管理
系统必须将对项目的修改和成员管理的权限限制为具有项目管理员角色的用户。

#### Scenario: 管理员修改项目信息
- **WHEN** 项目管理员更新项目名称或描述
- **THEN** 系统必须保存更改并返回更新后的项目详情

#### Scenario: 管理员更改成员角色
- **WHEN** 项目管理员将成员的角色从"普通成员"更改为"管理员"，或反之
- **THEN** 系统必须更新成员角色，并通过站内信通知被影响的用户

#### Scenario: 管理员移除成员
- **WHEN** 项目管理员从项目中移除一个成员
- **THEN** 系统必须删除成员资格记录，并通知被移除的用户

#### Scenario: 管理员不能移除自己是唯一管理员的情况
- **WHEN** 项目管理员尝试移除自己，或将自己降为"普通成员"（而自己是项目中唯一的管理员）
- **THEN** 系统必须返回 HTTP 400，错误消息为 "项目中至少需要保留一名管理员"

#### Scenario: 非管理员尝试修改项目
- **WHEN** 角色为"普通成员"的用户尝试修改项目名称、描述或管理成员
- **THEN** 系统必须返回 HTTP 403，错误消息为 "仅项目管理员可执行此操作"

### Requirement: 项目列表展示
系统必须按最近更新时间倒序展示用户参与的所有项目列表。

#### Scenario: 用户查看项目列表
- **WHEN** 已认证用户导航到项目列表页面
- **THEN** 系统必须显示用户作为成员的所有项目，按 `updated_at` 降序排列，并包含项目名称、描述、成员数量和最后更新时间

#### Scenario: 用户没有任何项目
- **WHEN** 已认证用户导航到项目列表页面但不是任何项目的成员
- **THEN** 系统必须显示空状态，并提示创建第一个项目

#### Scenario: 项目列表分页
- **WHEN** 用户拥有超过 20 个项目时
- **THEN** 系统必须以每页 20 个项目对项目列表进行分页
