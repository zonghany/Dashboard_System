## ADDED Requirements

### Requirement: 自定义看板列管理
系统必须支持对项目内自定义看板列的增删改查操作。

#### Scenario: 用户创建新的看板列
- **WHEN** 已认证项目成员使用有效名称和可选排序顺序创建一个新的看板列
- **THEN** 系统必须持久化该列（若未指定排序顺序则自动递增），通过 WebSocket 向所有连接的客户端广播新列，并返回 HTTP 201 的列详情

#### Scenario: 用户在同一项目中创建重复名称的列
- **WHEN** 用户在同一个项目中创建一个已存在的看板列名称
- **THEN** 系统必须返回 HTTP 409，错误消息为 "该列名已存在"

#### Scenario: 用户重命名看板列
- **WHEN** 用户重命名一个已存在的看板列
- **THEN** 系统必须更新列名，通过 WebSocket 广播更改，并返回更新后的列详情

#### Scenario: 用户重新排序看板列
- **WHEN** 用户更改看板列的排序顺序（如拖拽重排）
- **THEN** 系统必须原子地更新受影响列的排序顺序，并通过 WebSocket 向所有连接的客户端广播新的排序

#### Scenario: 用户确认后删除看板列
- **WHEN** 用户发起删除看板列的操作，系统弹出确认提示
- **THEN** 前端必须显示确认对话框，询问"确定要删除该列吗？该列下的所有任务将移动到「待办」默认列"；用户确认后，系统必须将删除列中的所有任务移动到默认"待办"列，删除列记录，并通过 WebSocket 广播列删除和任务移动

#### Scenario: 用户尝试删除最后一个看板列
- **WHEN** 用户尝试删除项目中唯一剩余的看板列
- **THEN** 系统必须返回 HTTP 400，错误消息为 "项目中至少需要保留一个看板列"

#### Scenario: 项目创建时的默认列
- **WHEN** 创建新项目时
- **THEN** 系统必须自动创建三个默认列："待办"（sort_order=1）、"进行中"（sort_order=2）、"已完成"（sort_order=3）

### Requirement: 任务卡片拖拽与实时同步
系统必须支持看板任务卡片的跨列拖拽，并通过 WebSocket 实现所有连接客户端的实时状态同步。

#### Scenario: 用户将任务卡片拖到不同列
- **WHEN** 用户将任务卡片从一个看板列拖到另一个列
- **THEN** 系统必须在 100ms 内更新任务所属列和目标列内的位置，持久化更改，并通过 WebSocket 向同一项目中所有在线客户端广播更新后的任务状态

#### Scenario: 用户在同一列内拖拽任务卡片重新排序
- **WHEN** 用户在同一看板列内将任务卡片拖到不同位置
- **THEN** 系统必须更新任务的排序顺序和受影响任务的排序顺序，持久化更改，并通过 WebSocket 广播新的排序

#### Scenario: 不同用户的并发拖拽操作
- **WHEN** 两个用户同时在同一项目中拖动不同的任务卡片
- **THEN** 系统必须独立处理两个操作，并向所有客户端广播每个更改；对于任何位置更新的冲突，采用 last-write-wins 策略

#### Scenario: 拖拽过程中 WebSocket 连接断开
- **WHEN** 用户在拖动任务卡片时 WebSocket 连接中断
- **THEN** 系统仍然必须通过 REST API 持久化拖拽操作结果；其他已连接的客户端必须收到更新；断开连接的用户必须在 WebSocket 重新连接后收到最新的看板状态

#### Scenario: 拖拽操作响应时间
- **WHEN** 用户完成拖放操作时
- **THEN** 系统必须在 100ms 内处理并持久化更改，WebSocket 广播必须在 500ms 内到达所有已连接的客户端

### Requirement: 列内快速创建任务
系统必须允许用户在特定看板列中快速创建新的空白任务卡片。

#### Scenario: 用户在列中点击"添加任务"
- **WHEN** 用户在特定看板列中点击"添加任务"按钮
- **THEN** 系统必须创建一个标题为空（占位文本为"新任务"）的任务，分配到该列，持久化，并通过 WebSocket 向所有连接的客户端广播新任务

#### Scenario: 新任务出现在列底部
- **WHEN** 在看板列中创建新任务时
- **THEN** 系统必须将新任务放在该列的底部（最高排序顺序位置）
